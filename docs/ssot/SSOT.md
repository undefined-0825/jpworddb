## 1. 最上位原則（MUST）

### 1.1 変更管理（MUST）

- Specは **Git管理**。変更は **必ずPR** 経由。
- **私（ちょび）のレビュー承認がない限り、docs配下のSpecは commit しない**。
- AIはローカル環境（`C:\dev\`）を参照できない前提。見た前提の断定は禁止。

### 1.2 仕様の唯一性（MUST）

- 「仕様」「ルール」「世界観」「禁止事項」は **Specファイルのみが正**。
- 会話中の説明・提案は正ではない。Specに反映され、レビュー承認されたものだけが正。

### 1.3 禁止（MUST）

- 勝手判断（良かれと思って補完・推測で埋める）禁止。判断不能は必ず質問。
- 虚偽報告（読んだ/検証した/出力したの断定）禁止。実施した手順・対象を併記できないなら「未確認」と書く。
- 仕様劣化（同じ概念の別名・別値・参照揺れ）禁止。
- /spec/ファイルの更新が必要な場合は、修正前にちょびさんに確認を取ってから修正すること。
- Spec本文へ **内部マーカー/混入ゴミ**を入れない（例：`filecite...`、turn番号等）。
- 世界観に合わない仕様の追加・改変を禁止。
- UI文言・設問文・ヘルプ文言で、日本語運用に不適切な文字（文字化け、簡体字、拡張漢字の混入）を禁止。
- **Git操作は明示的な指示なくして実行禁止**（MUST / 2026-03-21追加）：
  - `git add` → `git commit` → `git push` は別の指示。各段階で確認なく進めない。
  - 特に `git push` は **明示的に「pushする」と指示されない限り実行禁止**。
  - 例：「commit」と言われても、その後「push していいですか？」と確認してから実行する。

### 1.4 Spec管理のメタルール（MUST / 2026-03-06追加）

- 同じ内容を複数のSpecファイルに重複記載しない（重複禁止）。
- Spec修正時は、先に「どこに何を書くか」を決め、1箇所にのみ記載する。
- 配置原則は次の通り：
  - `project_rules.md`：失敗事例の要約のみ（詳細実装は参照）
  - `SSOT.md`：このメタルール自体
- 重複記載を避けるため、他Specからは「ファイル名 + セクション参照」でリンクする。

## 2. プロジェクト概要

### 2.1 目的

- 日本語の語彙データベース（jpworddb）を構築し、モバイルアプリから参照・学習できる仕組みを提供する。
- 初期フェーズは **四字熟語** のスクレイピングによるデータ収集から開始する。

### 2.2 技術スタック

| レイヤー | 技術 |
|---|---|
| スクレイピング | Python（詳細は `spec_scraping_yojijukugo.md` 参照） |
| データ形式 | TXT（UTF-8、1行1レコード） |
| クライアント | Android / iOS（モバイルアプリ） |

### 2.3 Spec一覧

| ファイル名 | 内容 |
|---|---|
| `docs/ssot/SSOT.md` | このファイル。AI作業の入口 |
| `docs/spec/spec_scraping_yojijukugo.md` | 四字熟語スクレイピング仕様 |

## 3. 実装ルール（MUST）

### 3.1 対象OS・プラットフォーム

#### 3.1.1 対象OSの厳格化（MUST）

- 本プロジェクトのクライアント実装対象は **Android / iPhone（iOS） のみ**。
- **Windows / macOS / Linux 向けのアプリ実装・コード生成・ビルド手順・設定（例：WinUI/WPF/UWP、MAUIのWindowsターゲット、Electron、.dmg/.msi、Desktop向けCI、OS別パス前提の実装）は提案・実装ともに禁止**。
- 例外は **サーバ/CI等の開発環境の補助**（例：PowerShellやbashでのローカル起動、lint、unit test）に限る。ただし、クライアント機能の実装がDesktop向けに拡張される提案は禁止。

### 3.2 スクレイピング

- 詳細仕様は [`docs/spec/spec_scraping_yojijukugo.md`](../spec/spec_scraping_yojijukugo.md) を参照。
- スクレイピング対象サイトの利用規約・robots.txtを遵守すること。
- 対象サイトに過負荷をかけない実装（リクエスト間隔の確保等）を必須とする。

### 3.3 データ管理

- スクレイピング結果のTXTファイルは `data/` ディレクトリ配下に格納する（TBD）。
- データファイルのGit管理可否は別途決定する（デフォルトは `.gitignore` 対象）。

### 3.4 文字運用

#### 3.4.1 日本語文字運用（MUST）

- ユーザー向け文言（画面表示、設問、説明文、エラー文）は日本語として自然な文字のみを使用する。
- 漢字は日本語運用で一般的に使用される字形を使い、簡体字・文字化け・意図しない拡張漢字を混入させない。
- 文言変更時は、実装前後で文字化け/字形異常の目視確認を行う。

### 3.5 テスト/CI/コストガード（MUST）

- 現時点は **CIのみ**（自動デプロイなし）。
